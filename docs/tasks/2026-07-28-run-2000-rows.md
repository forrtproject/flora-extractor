## Environment — do this first, it is not optional

**There is no `.env` file in the repo.** Without the two lines above, `shared/config.py`
silently falls back to `RESEARCHER_EMAIL='research@example.com'` and zero Gemini keys.
The consequences are not obvious failures: OpenAlex and CrossRef throttle the
placeholder mailto, and every Gemini call fails over to OpenAI. A previous session lost
three hours to this. Verify before launching:

```bash

```

Expect ≥1 Gemini key, OpenAI True, the real email, and 5 OpenAlex keys.

**OpenAlex bills per request against a daily budget that resets at midnight UTC.** Four
of the five keys were exhausted on 2026-07-27; the fifth was fresh. Rotation is
automatic on a budget refusal, but when *every* key is drained the run now stops with
`OpenAlexQuotaExhausted` rather than silently degrading. If that happens: top up at
<https://openalex.org/pricing> or wait for the reset, then re-run with `--resume` — rows
already written are intact.

Costs, measured: ID lookups and 50-DOI batch fetches are $0.0001 each; free-text
searches are **$0.001** (10×). A 2,000-row run should be roughly $5–15 of OpenAlex plus
a few dollars of LLM. If it looks like heading past ~$25, stop and ask.

**Dependencies**: if `filelock` or similar is missing, `.venv/bin/pip install -r
requirements.txt`. **Data**: `data/filtered.csv` (~4.9 GB) must exist; if not,
`./scripts/data.sh pull` — but note that script calls `python`, which is not on PATH,
so use `.venv/bin/python -m zipfile -e filtered.zip .` from `data/` instead.

## How the pipeline now works

`run_for_doi()` in `extract/link_original.py` escalates cheapest-first and returns at
the first stage that resolves. `CLAUDE.md` documents the full ladder. The parts that
matter for interpreting your results:

| Stage | What it does | Outcome |
| --- | --- | --- |
| 2–4 | OpenAlex candidates, title pattern, rule-based, cited-candidate LLM | all need an author–year citation *in the abstract*; most rows have none |
| **4.5** | **Two-model replication screen** | discard / resolve / disagree |
| 4.6 | Title search on a target the screen named but couldn't match | `llm_title_search` |
| 5 | PDF acquisition + full-text LLM | `llm_fulltext` |

**Stage 4.5 is where most of the work now happens.** Q1 ("is this a replication?") runs
on `gemini-3.5-flash-lite` *and* `gpt-5-mini`. A row is discarded only when both agree
at high confidence. Q2 ("which reference is the target?") is a separate call, made only
when Q1 says yes, with its own confidence; a target is accepted only at high confidence.

Three outputs are quarantined by `extract/sanity_check.py`, which runs automatically at
the end of the run **and on Ctrl-C**:

- `data/not_a_replication.csv` — both models agreed it isn't a replication
- `data/screen_disagreement.csv` — models disagreed; `link_evidence` records each
  verdict, e.g. `screen disagreement: gemini=no/high; openai=yes/high`
- `data/target_pending.csv` — includes rows where no document could be obtained

## Baseline numbers to compare against

From a 78-row sample on 2026-07-27:

| Path | Share |
| --- | --- |
| Discarded — not a replication | 36% |
| Resolved from reference list | 15% |
| Resolved by pre-PDF title search | 1% |
| Resolved from cited candidates | 4% |
| Stopped — no document obtainable | 22% |
| PDF acquired and parsed | 22% |

Other measured baselines: **model agreement 68%**; **~45–55% of Stage-3 input is not a
replication at all** (a Stage-2 precision problem, stable across two samples); PDF
acquisition returns nothing **62%** of the time; roughly **1 `failure` outcome per 19
written rows**.

At 2,000 rows these percentages should be far more trustworthy than the small samples
above. Report where they diverge — divergence is the interesting result.

## What to report

1. **Pathway spread** over the 2,000 rows, as a table comparable to the baseline.
2. **Model agreement rate**, and — new, now that individual votes are stored — *how*
   they disagree. Is one model systematically stricter? Do disagreements cluster by
   field or paper type? Several observed disagreements were **both models at high
   confidence in opposite directions**, which nobody has explained yet.
3. **Validation by hand.** Sample ~30 rows from `not_a_replication.csv` and ~20 from
   `screen_disagreement.csv`, read title and abstract, and judge each. Report precision
   and describe the error *pattern*, not just a count. Do not skip this because the
   aggregate numbers look fine — the last two rounds of real findings came from reading
   abstracts, not from counters.
4. **Outcome distribution** and the `failure` yield per written row.
5. **Cost actually spent** (OpenAlex and LLM), against the estimate above.

## The classification rule

**A replication re-tests a previously published finding.** Re-testing in a new
population or country counts. These do **not** count, and the prompt says so:

- validating, adapting or comparing a *measurement instrument* — cross-cultural
  adaptation, test-retest or inter-rater reliability, inter-laboratory method comparison
- non-research senses: DNA/viral replication, replicating a disease phenotype in an
  animal model, rolling out a programme elsewhere, a surgical technique that
  "replicates" an open approach

Use this rule when validating by hand. If you think the rule itself is wrong for a case,
say so rather than quietly applying a different one.

## Lessons learned — read these

**Do not trust a rate computed over a corpus you haven't segmented.** The single worst
error of the previous session was quoting a 5.4% PDF-escalation rate from
`extracted.csv`, where 1,151 of 1,714 rows came from a legacy pipeline. The real rate on
fresh rows was 92%. This produced a 10-hour estimate for work that would have taken six
days.

**A silently-swallowed error looks exactly like a real result.** A quota 429 became
`None` became `[]` became "this paper has no candidate originals" became a PDF fetch.
Nothing in the output distinguished it from a genuine empty result. When a stage reports
zero of something, confirm it is a real zero.

**Tests that pass may be passing for the wrong reason.** Two tests passed only *because*
the quota failure was silent; fixing the bug turned them red. They also made live API
calls despite claiming "all API calls mocked". See issue #75 — the suite still contains
network-bound tests, and a full `pytest tests/` run takes minutes and is flaky. Run
`.venv/bin/python -m pytest tests/ -q --ignore=tests/test_analysis_overlap.py` (that one
needs `data/all_replications.csv`, which may be absent). Expect 535 passed, 20 skipped.

**Prompt changes need a version bump.** The screen cache key includes
`REF_SCREEN_PROMPT_VERSION` in `shared/llm_client.py`. Change the prompt without
bumping it and you will read back results from the old prompt and conclude the change
did nothing.

**`--limit` counts processed rows, not scanned rows.** Rows skipped by `--resume`, by
the test-mode production skip, or as false positives are free. But **without
`--resume`, `--extracted-test` truncates its own output and never skips DOIs it
processed on a previous test run** — so successive batches replay the same rows. That is
why `--resume` is in the command above. (It is not a bug: identical row sets are what
makes two prompt versions comparable.)

**Verify visually, not by reading code.** "The screen rejected 19 papers" and "19
rejections reached the quarantine file" turned out to be different numbers — a guard
was rewriting rows and `--resolved-only` was dropping them. Check the files on disk.

## If something goes wrong

- **Run dies mid-way**: rows already written are intact; re-run with `--resume`.
- **`data/extracted.csv` looks truncated during a run**: `--resume` rewrites it from
  scratch, so it is temporarily short. It is tracked in git — `git checkout --
  data/extracted.csv` restores the committed state. Do not panic-kill on row count alone.
- **Ctrl-C**: safe. `sanity_check` still runs.
- **429s from OpenAlex**: transient ones retry (5/15/30s). Budget refusals rotate keys
  and then stop the run — that is intended.
- **Before committing anything**, `git checkout -- data/` to drop CSV churn from test
  runs, unless the data change is the point.
