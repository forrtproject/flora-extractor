# Discard-gate sweep — prompt_v32, corrected truth labels

Generated by `gate_sweep_v32.py` from the `voter_v32_*` and `voter_v3_*` result files in this directory. No API calls. Truth: the corrected labels `human_truth_v32.json` (60 cases, 13 yes / 47 no), `heldout_truth_v32.json` (30, 10 yes / 20 no) and the 300 FLoRA entries in `flora_positive_cases.json` (all yes) — 320 positives, 70 hard negatives.

Every gate is written over the v3.2 binary `confident` field. v3 is swept alongside with `confidence == "high"` read as `confident`, so the same gate name means the same rule under both prompts.

These cases are derivation data (see `README.md`), so every number is in-sample. `schema_error` / `api_error` rows count as *not answered*, so a model that failed to answer can never contribute to a discard.

`F140` is an adjudication-pending FLoRA entry and is counted separately from the settled misses.

The 150-case proxy pool (`coding_v3_cases.json`, past production discards) was only run through flash-lite, so its column is a **single-model analogue** of each gate — for the soft gates, the confident-`none` half, since the qualifying-side clause needs a partner. It is comparable across prompts in level, but not to the hard-negative column.

- **T-unan** — all 3 none, any confidence

- **T-softqual** — all 3 none, or >=1 none+confident with every other voter unconfident qualifying-or-unclear

- **T-maj-soft** — >=2 none (>=1 confident) and no voter asserts qualifying at confident=true
- **T-maj-soft-strict** — >=2 none (>=1 confident) and the third is none or an unconfident unclear
