2 · What the pipeline now does differently

  • Multi-original papers run through the per-target adapter. The target prompt's validated list is consumed directly: per target — key-record resolution, link guard, DOI verification, then one extract_outcome call (escalation, record_type_check veto and the reproduction grid all apply; the multi_original flag is in the outcome cache key only when set). One row per original paper; same-paper studies collapse with study numbers joined; after guard/verification the group is deduplicated by final doi_o, renumbered, and match type + confidence are settled from what was actually written. study_r (which study in the replication maps to this original) is populated on both link paths.
  • No rule ever asserts multiple_original. The match-type router is gone. A deterministic ladder rung may end a row only when title+abstract carry exactly one author-year pair and no study count; otherwise its pick is withheld, and restored at any exit where no enumerating LLM call succeeded (or where the call agreed with it). A transient API failure never converts a rule resolution into a loss, and a restore never overrides a contradicting answer.
  • Full-text provenance is on the row. pdf_source (acquisition tier) and parse_method (winning parser) are CSV columns, imported by csv_to_db once the DB has them. The landing-page HTML substitute is deleted; a content-free OpenAlex XML shell counts as no document.
  • The OpenAlex XML tier works and is the cheapest document source. The endpoint was alive all along; our client never gunzipped the payload and the parser assumed camelCase TEI where OpenAlex serves HTML-lowercased copies. Now one parser serves both dialects; body text (bibliography excluded, structure preserved) feeds the target prompt's INTRODUCTION block and outcome escalation. The endpoint is metered — $0.01/download against a $1/day free tier — so it is key-gated, rotated, and each work is fetched once and cached. Verified live: W2982430379 → 32 references, 28k chars, outcome evidence provenance discussion.
  • Prompts: screen v3.3 + FAQ rules. The overlap clause is in WHAT QUALIFIES; five FAQ outcome rules (failed manipulation check → failure; failing title effect → failure; conceptual close-but-fails → mixed; centrality; aggregation scope) are in the replication outcome prompt, the two shared ones in the reproduction prompt, and the replication-chain rule (nearest successor) in the target prompt. Three wording resolutions are flagged in PR #126 for maintainer confirmation.
  • Spend levers. Gemini flex on (.env). OpenAI flex implemented but default-off (OPENAI_USE_FLEX) — flipping it is a one-line action (§6.1). GEMINI_THINKING_LEVEL exists, default unset, awaiting its quality spot-check (§6.3); when set it is folded into the heavy-model cache keys.

6 · The work plan — every remaining step, in order

The boundary rule, restated once. PR #126 re-voted everything: no LLM verdict on disk replays. That is spent — but it also means the next prompt edit re-votes the corpus again. So: any further prompt change (the flagged FAQ wordings, a v3.4 clause, WP4's trim if adopted) must be bundled and land before the full re-run, or wait for the run after it. Steps 6.1–6.3 are cheap and reversible; 6.4 is the big spend and should come after 6.1–6.3 and any prompt bundle are settled.

6.2 · The rescreen run ~$4, one afternoon

Re-extract extracted.csv + all set-asides (~3,200 rows) under the final prompts and code. Verify afterwards: sanity_check clean; audit_dois pass; outcome distribution compared against the old file (large shifts explained, not assumed); hand spot-check ~20 rows stratified by link method; the provenance columns audited against cache/pdfs the way §3's audit did.
